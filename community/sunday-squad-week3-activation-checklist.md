## Goal tie: 20 WAU / 100 human messages

Definitions live in `docs/COMMUNITY_SCORECARD.md`: weekly active = distinct
eligible humans with one eligible message or ≥600 unioned voice seconds;
human messages = eligible `message_created` facts only. One pilot evening
cannot produce 20 WAU by itself — week 3's job is (a) not to drag the goal
(bot noise, broken capture) and (b) to set up the week-4 finale that
contributes to it. The gates below enforce exactly that.

- [ ] Confirm the slot is wall-clock **Sunday 20:00 America/New_York**, not

## Gate A — T-72h readiness (5 min, by Thu 8 Oct EOD)

- [ ] Host named: `[HOST]` · Backup named: `[BACKUP]` · both confirmed
      available for Sun 11 Oct 20:00 ET.

## Gate B — T-24h go / no-go (5 min, Sat 10 Oct)

- [ ] Host or backup available for tomorrow 20:00 ET. (Squad has no RSVP;
      availability, not headcount, is the go criterion.)
- [ ] Neither available → pre-draft the kit §3 path-C cancellation note now
      (fill `[N]`, `[TIME]` on the day); notify the CM. No substitute is
      drafted same-day.
- [ ] **Gate:** go = at least one of host/backup confirmed. No-go =
      cancellation note staged, CM notified, retro (§4) still gets filled.

## Gate C — T-30min voice check (5 min, Sun 11 Oct 19:30 ET)

- [ ] Host joins Lobby voice from the event device.
- [ ] Connects and is heard → run kit §2 (voice path).
- [ ] Cannot connect / cannot be heard → 10-minute retry box (rejoin,
      restart client, try mobile), then declare exactly one of kit §3
      paths A (text-channel party), B (in-room play, option named in
      advance), or C (cancel truthfully, post by 20:15).
- [ ] **Gate:** the host never no-shows silently and never improvises a
      second event. Rules: no DMs to round people up, no second RSVP path,
      heads-at-doors logged as-is.

## During (the event hour — excluded from the 30-min budget)

- [ ] Host runs kit §2 (or the declared §3 path); hard stop 21:00 ET.
- [ ] Backup captures notes; attendance proof method ready
      (RSVP is not attendance — see `docs/COMMUNITY_SCORECARD.md`).
- [ ] One feedback question only: "what one thing should the regular run
      keep?" — recorded, never debated.

## Step +48h — retro + goal gate (10 min, by Tue 13 Oct)

- [ ] Host fills the kit §4 retro (facts only; IDs and timestamps, never
      message text, per `docs/PRIVACY.md`); recap posted within +48h either
      way, quiet weeks reported as-is.
- [ ] **Goal gate G1 — capture complete:** weekly scorecard run shows
      `coverage_state` complete. If `incomplete`, repair capture first —
      do not change programming from an incomplete scorecard.
- [ ] **Goal gate G2 — bot noise <20%:** if the scorecard alerts at ≥20%,
      fix noise before reading engagement numbers.
- [ ] **Goal gate G3 — progress recorded:** log week-3 eligible attendance +
      event-linked eligible messages and the running weekly WAU / human-message

- [ ] **Goal gate G4 — finale readiness flags** (record only — the CM owns

      non-staff humans who returned at least once (flag if `<2`);
      host/backup availability for week 4 (Y/N + names).
- [ ] **Gate:** retro + four goal gates recorded → week-3 activation done;
      the week-4 finale decision belongs to the CM.

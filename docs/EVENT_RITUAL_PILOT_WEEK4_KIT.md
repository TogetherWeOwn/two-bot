## 1. Agenda template (60-minute default; 90-minute extension below)

Week 4 closes the pilot, it does not relaunch it. The through-line is: same slot, same shape, land what weeks 1–3 opened and hand the pilot record to the CM.

| Clock | Block | Owner | Notes |
|---|---|---|---|
| 0:00–0:05 | Doors / landing | Host | Early arrivals settle; backup has the weeks 1–3 notes + all three posted recaps open. No content yet. |
| 0:05–0:12 | Three-week bridge | Host | One factual recap line each from `[WEEK-1-RECAP-LINK]`, `[WEEK-2-RECAP-LINK]`, and `[WEEK-3-RECAP-LINK]` (what happened, not what it meant) + the finale through-line: "we surfaced X, went deeper on Y, paid off Z; today we close out `[TOPIC]` and the pilot." Never re-run weeks 1–3. |
| 0:12–0:18 | Intros, two-track | Host | Returners: handle + one-word check-in. Newcomers: handle + one-line answer to `[PARTICIPATION-PROMPT]`; host gives a 30-second catch-up on the three-week arc (the room does not). |
| 0:18–0:40 | Core activity, finale | Host facilitates, backup captures | Converges on `[TOPIC]`: resolve or advance the remaining open stucks carried from weeks 1–3. Host keeps turns short; backup logs aggregate points only (no verbatim quotes without consent). |
| 0:40–0:50 | Retrospective: wins, stucks & pilot verdict | Host | Round-robin; pass allowed. Each person: one win from the pilot, one stuck that remains, one sentence on "should this ritual continue?" — host records, never debates. Newcomers: one win + one stuck, 1 minute each. |
| 0:50–0:57 | Close + what-happens-next | Host | Thank everyone by name (returners) / by handle (newcomers); recap lands in `[CHANNEL]` within 48h either way; state plainly: "the pilot ends here — the CM decides next steps from the four-week record, nothing is promised tonight." One feedback question: "what one thing would you keep?" |
| 0:57–1:00 | Buffer / hard stop | Host | Overrun guard. Host ends on time even mid-thread; unfinished items go into the recap as open stucks for the CM record, not into a week 5. |

**90-minute extension** (use only if the 5+ responses confirm 90): bridge + intros unchanged; core activity expands to 0:18–1:00 with a 10-minute break at ~0:48; retrospective 1:00–1:20; close 1:20–1:30.

**Newcomers:** welcomed by name, given the catch-up, never quizzed on weeks 1–3 content, never singled out for extra turns. **Returners:** acknowledged by name, not tasked (no on-the-spot hosting asks). **What the host does NOT do:** no DMs, no second RSVP path, no presenting bot output as human conversation, no attendance/quote inflation, no weeks 1–3 re-run for latecomers, no freelance moderation (escalate disruption to CM/mods per existing server process), no promising a post-pilot series.

## 2. Host checklist

### T-72h
- [ ] Host + backup confirm availability for the same slot; backup reachable on event day.
- [ ] Host re-reads weeks 1–3 notes + all three posted recaps; carries remaining open stucks forward into the core-activity plan.
- [ ] Single in-server announcement posted (final Content Producer week-4 copy — continuity line references the posted recaps only, never invented attendance; finale framing: "final pilot session"); `[RSVP-ACTION]` verified live and canonical-only.

### T-24h — go / no-go
- [ ] Count RSVPs. **Fewer than 3 → cancel this instance**: post the cancellation note ("Week [N] cancelled ([N] RSVPs, needed 3). Next try: [DAY/TIME]."), notify backup, log the count truthfully. No substitute drafted same-day. A cancelled week 4 still gets a pilot-record note (see +24–48h).
- [ ] 3+ → confirm host/backup, prep the 30-second three-week catch-up + `[PARTICIPATION-PROMPT]` + notes doc (weeks 1–3 summary pasted at top), verify channel/voice access.
- [ ] Log RSVP count alongside weeks 1–3 for the record only — no spin, no lowering the bar.

### T-1h to doors
- [ ] Notes doc open with weeks 1–3 summary at top; attendance proof method ready (canonical [TOG-1649](/TOG/issues/TOG-1649) method — **RSVP is not attendance**).
- [ ] Any automation labeled; reminder sent **only** to RSVP-yes / "remind me" replies.

### During
- [ ] Run the agenda; hard stop on time.
- [ ] Record attendance only via the canonical proof method; record host/backup staff/non-staff status; tag returner vs newcomer only if computable via the canonical method, else omit.
- [ ] Backup captures aggregate notes; no verbatim quotes without explicit consent.
- [ ] Capture the retrospective answers verbatim-in-aggregate (one win / one stuck / continue-sentence per person, anonymized unless consent).

### +0–2h
- [ ] Host + backup debrief (what worked, headcount, issues) in the notes doc, including the factual week-over-week comparison (RSVP deltas, weeks 1→2→3→4 return chain, newcomer count).

### +24–48h — truthful follow-up (one post)
- [ ] Recap posted: eligible attendance `[N]` + proof method; returner/newcomer split only if computable, else omit; 1–2 factual aggregate lines including one continuity line vs week 3; pilot-close line ("pilot complete — CM reviews the four-week record; no next session scheduled") with no new `[RSVP-ACTION]`.
- [ ] Quiet or cancelled weeks reported as-is. Never invent attendance, quotes, or activity. Named thanks only with separate recap opt-in (first name/handle per their choice).

### Kill / pivot (per brief — host enforces, CM owns the call)
- Cancel an instance under 3 RSVPs at T-24h; change topic/time after two sub-5 events; end the format if fewer than two non-staff humans return or nobody will host/help.
- Week 4 is the fourth and final data point for the "two sub-5 events" and "fewer than two non-staff humans return" signals — the host records them, the CM makes the call. The host never pivots the format mid-pilot and never schedules a post-pilot session.

### Instrumentation to record each week (pilot evidence)
Event created · RSVP transitions · eligible attendance + proof method · first-time/returning split (if computable) · weeks-1→2→3→4 return chain + newcomer count · follow-up posted (Y/N + link) · event-linked eligible messages · host/backup names + staff/non-staff flags · bot-noise check (<20%) · retrospective rollup (keep-one-thing answers, anonymized) → handed to CM as the pilot record.
